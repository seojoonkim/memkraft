# MemKraft 3.0.1 Reliability Patch Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship MemKraft 3.0.1 as a tightly-scoped, additive, read-compatible reliability patch that makes lifecycle freshness observable, closes explicitly opted-in preview candidate governance gaps, improves deterministic English/Korean claim precision, and makes the Memory Gym catch those regressions.

**Architecture:** Keep markdown as durable user source material. Keep `.memkraft/` logs append-only and derived views/caches rebuildable. Do not auto-compile truth on reads; expose freshness state instead. New candidate governance applies only to preview candidate sidecars and structured claims, never implicitly to legacy markdown `search()`.

**Tech Stack:** Python 3.9+, stdlib JSONL/`fcntl` storage, pytest, Memory Gym CLI, GitHub Actions.

---

## Verified baseline and release framing

- Released baseline: `3.0.0`, additive/read-compatible with `2.13.x`.
- `current_truth()` reads `compiled_truth.jsonl`; after a newer `append_event()` it can return the prior compiled value until `sleep(dry_run=False)` or `compile_truth(dry_run=False)` runs.
- The behavior is reproducible locally: compiled `city=old`, followed by event `city=new`, returns `{'city': 'old'}`.
- `extract_claims('Alice prefers dark mode (maybe).')` currently returns a `0.9` claim, while `extract_claims('철수가 파이썬을 선호한다')` returns no claim.
- Existing Memory Gym CI executes `session_overlay_recall`, `resolver_verdicts`, and `last_interaction` without `--gate`.
- Candidate sidecars are preview APIs. Current 3.0 governance contract explicitly controls canonical `.memkraft/events.jsonl`; extending policy behavior to structured preview candidates is a **new, explicit preview contract**, not a retroactive bug claim.

## Non-negotiable invariants

1. Existing stable APIs and positional semantics remain intact.
2. No destructive migration and no rewrite of user-authored markdown.
3. Search remains available if every derived view/cache is absent.
4. New destructive API behavior defaults to `dry_run=True`.
5. Preview APIs remain preview; do not promote stability in this release.
6. Do not introduce LLM/NLP dependencies or internal network calls.
7. Do not claim backup erasure. Local sidecar compaction only physically removes matching local JSONL lines.

## Release cut

**Target:** `3.0.1`

**Included:**
1. Memory Gym correctness/gate hardening.
2. Candidate preview governance + supported local maintenance.
3. Observable compiled-truth freshness + behavior-preserving read cache.
4. Deterministic claim extraction precision and Korean coverage.

**Explicitly deferred to 3.1+/3.2+:** outcome cold-start priors/decay-floor changes, ranking policy changes, `context_utility` cache/compaction, Korean relative-date extraction, LLM extraction, broad benchmark-suite expansion, and governance filtering of legacy markdown search.

**Step 1: Write failing freshness tests**

3. assert `current_truth('u') == {'city': 'old'}` (existing behavior is intentionally retained);

**Step 2: Implement `truth_status()` preview API**

Return a deterministic, JSON-serializable shape:
```python
{
  "schema_version": 1,
  "stale": bool,
  "live_transaction_id": str,
  "applied_transaction_id": str | None,
  "pending_event_count": int,
```

**Step 3: Add an mtime+size snapshot cache to `current_truth()`**

- Key cache on events and compiled truth `(mtime_ns, size)`.
- Do not cache policy checks: `do_not_remember` must take effect immediately.
- External deletion/corruption of a derived view must fail closed/gracefully, never make search unavailable.

**Step 4: Add a benchmark before claiming performance**

`benchmarks/derived_views_bench.py` reports cold and warm repeated `current_truth()` timing at fixed sizes. Commit real before/after JSON artifacts; do not set a new hard target without a baseline.

**Step 5: Add Gym gate**

## Risk register

- **Candidate scope ambiguity:** policy-filter only structured claims; free-text candidates require explicit candidate deletion. Do not silently invent text-policy semantics.
- **Filesystem cache correctness:** cache keys include mtime and size; policy checks stay live.
- **Compaction races:** reuse store-core locking and add concurrent append/compact regression coverage.
- **Korean overmatching:** constrain new particles/enders with explicit fixtures; reject rather than guess.
- **CI latency flake:** do not tighten last-interaction latency thresholds without measured repeated CI data.

## Final release gates

- Full pytest passes with no removed/weakened regression tests.
- Every Gym scenario invoked by CI uses `--gate`.
- New gates pass: precision, Korean recall, end-to-end extraction, governed candidate absence, truth freshness.
- Compaction preserves all public visible reads before vs. after apply.
- Cached `current_truth()` exactly matches direct-read behavior across governance cases.
- Real before/after derived-view benchmark artifacts are committed; no invented performance claim.
- Fresh wheel install and CLI/provider smoke pass.
- Documentation distinguishes canonical governance, preview candidate governance, local compaction, and backup limits.
