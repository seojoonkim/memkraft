## MemKraft 4.2.1

Performance and recall-quality patch. No migration required.

- Faster search on large stores: the corpus fingerprint is computed from
  `os.scandir` stat tuples, and `Path` objects are built only when the index
  must be rebuilt. The read cache keeps one entry per path in a side index, so
  cache misses and invalidation no longer scan every resident entry.
- Template-safe Hermes prefetch: chat-derived template entity pages can win
  every top-12 slot through the filename bonus. Prefetch now widens its
  candidate window (12 → 80 → 240) until real documents surface, and only falls
  back to template pages when nothing else matches.
- UTF-8 corruption handling: undecodable JSONL records are skipped and counted
  per record instead of failing the whole read; reads, compaction and preview
  share one parser.

### Verification

- Full MemKraft test suite: 3,740 passed, 17 skipped.
- Real 30,082-file Hermes store copy, uncached `search(top_k=20)` median:
  333 → 160 ms, 245 → 132 ms, 298 → 158 ms.
- Same store, Hermes prefetch for a deploy/install question: 5 of 5 recalled
  items were template entity pages before; 0 of 5 after.
