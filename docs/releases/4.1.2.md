## MemKraft 4.1.2

This release makes Delay Ledger writes linear in ledger size.

- Each append now folds the ledger once and reuses that fold for its
  integrity check, predecessor validation and ETA estimate.
- The fold keeps incremental per-(kind, subject) completed-sample series and
  open-child counts instead of rescanning every run, so replay is linear.
- Replay semantics, fail-closed corruption handling and anomaly thresholds are
  unchanged. No data migration is required.

Hermes records about four delay events per tool step. On a 24,285-event
production ledger the previous quadratic fold added roughly 55 seconds to
every tool step; measured on a copy of that ledger, one fold dropped from
5.32 s to 0.18 s and four appends from 50.8 s to 1.3 s.

MemKraft 4.1.1 was never published to PyPI, so 4.1.2 also carries the
verified WikiSkill experience pipeline described in
[4.1.1 release notes](4.1.1.md).
