## MemKraft 3.3.0

MemKraft 3.3.0 introduces MKEP/0, a runtime-neutral execution protocol Preview. The GA decision deadline is **2027-02-04**.

### Highlights

- Append-only deterministic execution projection with goals, gates, evidence receipts, advisory assessments, leases/fences, and typed cross-base handoffs.
- Closed 15-operation Python/CLI protocol surface and read-only MCP projection.
- 32 named conformance cases in a 167-directory corpus, with a Go read-and-verify runner for MKCJSON/1 CJ-03 bytes/digests and XR-01 cross-language handoff integrity/replay/conflict behavior.
- Graph Engineering adapter examples for Claude Code Dynamic Workflows, LangGraph, and Temporal. Topology, merge, verifier independence, scheduling, and checkpoint/resume stay runtime-owned; their resume/checkpoint semantics are non-equivalent and MKEP adds no graph schema.
- Dual-opt-in execution context preserving byte-identical legacy behavior when unused.
- A fingerprint-invalidated local projection sidecar keeps repeated `state.read`
  calls bounded without changing the append-only log. Missing, stale, corrupt,
  or deleted cache entries are rebuilt from the authoritative log; deleting the
  cache produces byte-identical protocol output.

### Quantitative release gates

The checked-in `scripts/benchmark_execution_gates.py` generates the locked
40-goal corpus and measures 20 warmups followed by 200 repetitions on one
runner. The final macOS arm64 result is stored at
`docs/bench/results/mkep-3.3.0-g11-g12-macos-arm64.json`.

- **G11 projection performance:** p95 ratio **0.9750×** for 10,000 versus
  1,000 records per goal, under the blocking limit of 12×. Standard-corpus p95
  was **0.039 ms**, below the 150 ms soft-warning ceiling.
- **G12 CLI transport latency:** `state.read` p95 **61.313 ms** versus
  `memkraft --version` p95 **73.186 ms**, a **-11.873 ms** margin under the
  blocking +400 ms limit.

These are comparative measurements from the named machine class, not universal
latency claims. Re-run the script on CI/release hardware rather than carrying
the absolute numbers forward.

### Compatibility and limits

No migration is required. Execution files are lazy-created under `.memkraft/execution/`; 3.2.x ignores them, and re-upgrading resumes the retained log. The log is not compacted in 3.3.0.

MKEP/0 is local-filesystem and single-host only. Gates and assessments are advisory, authority and runtime identities are not authenticated, artifact hashes are caller assertions, and handoff digests establish self-consistency rather than sender authenticity. It provides no scheduler, graph engine, multi-host consensus, network-filesystem guarantee, or authorization mechanism.
