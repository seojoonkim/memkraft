## MemKraft 4.3.1

Shared owner-ledger patch. No migration required.

- `MemKraft(base_dir=...)` resolves the owner ledger from `MEMKRAFT_OWNER_DIR`
  when it is set, the same directory the Hermes provider already uses. Before
  this, a script that recorded an owner saying with a plain store wrote it to
  `<base_dir>/owner/sayings.jsonl`, where `owner_saying_search` in Hermes never
  saw it. An explicitly assigned `owner_dir` still takes precedence; without the
  env var the per-store default is unchanged.
- New `memkraft owner` CLI: `search <query> [--scope]`, `record <text> [--scope]
  [--tag] [--source]`, `decisions` (open decision digest), `where` (resolved
  directory).

### Upgrading

Sayings already written to a per-store `owner/sayings.jsonl` stay there. To share
them, re-record each one with `memkraft owner record` while
`MEMKRAFT_OWNER_DIR` points at the shared directory; records are deduplicated.

### Verification

- `tests/test_owner_dir_shared.py` (env resolution, explicit override, unchanged
  default, CLI round trip) and the existing owner-ledger tests pass.
- Real Hermes setup: 6 sayings that a cron script had stored in per-profile
  folders were moved to the shared ledger and are now returned by
  `owner_saying_search`.
