## MemKraft 4.2.2

Cold-start recall patch. No migration required.

- Persistent token cache: per-document token-frequency maps and the derived
  postings are stored in `.memkraft/index/corpus-tokens-v1.bin`, keyed by each
  file's `(mtime_ns, size)` and the tokenizer. A restarted process re-reads
  only changed documents, and restores the whole index directly when nothing
  changed. Corrupt, truncated, or foreign cache files fall back to a normal
  rebuild. `MEMKRAFT_INDEX_CACHE=off` disables the cache.
- Faster rebuild loop: document frequency is derived from posting lengths
  instead of a second dictionary update per token.
- Hermes stat-scan TTL: the provider reuses a verified store scan for 15 s
  between turns (`MEMKRAFT_HERMES_STAT_TTL`, `0` disables). Provider writes
  still invalidate immediately; edits from other processes appear within the
  window. The library default stays exact (TTL off).
- JSONL store reads: `read_all()` ignores an unterminated, unparsable final
  line as an append still in flight instead of counting it as corrupt, and
  `append()` loops until the whole record is written.

### Verification

- Full MemKraft test suite: 3,689 passed, 15 skipped (release-gate tests run
  separately); Hermes provider, compat, and persistent-cache tests: 54 passed.
- Real 30,082-file Hermes store copy, first prefetch after process start:
  2.0-3.9 s before, about 0.55 s with a warm cache file. Cache file 9.8 MB.
- Same store, prefetch for new questions (search cache miss): medians 123-434 ms
  before, 12-140 ms after. Recalled documents are unchanged.
